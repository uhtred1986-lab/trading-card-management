# Route capabilities and proposed navigation

Proposal from the current local source snapshot, 15 October 2026. This maps existing capabilities; it does not change production routes or authorize implementation. Every `src/app/**/page.tsx`, `route.ts` and the generated app manifest has a record in the companion JSON array. Each record includes the source file. Route patterns retain dynamic identifiers. Query states and server actions belong to their owning screen; they are not invented URLs.

## Navigation model

Desktop primary navigation: **Home · Collection · Cards · Decks · Arena · Insights**. Keep **Add cards** as an always-discoverable action into Collection capture, not as a vanished feature. Account and Settings sit in the utility menu. Admin is an SL-only utility group; it does not require a new `/admin` route. Insights is the proposed label for the existing `/meta` and `/meta/news` routes, not a claim that `/insights` already exists.

Phone: preserve the current Arena-first principle, with **Arena · Collection · Cards · Decks · Add** in the bottom bar. Home remains on the wordmark, with Insights and account in More. The navigation structure is identical in both themes. Active online/local boards retain the established full-bleed presentation and their own exit controls; do not force the global bottom bar over the hand.

## Secondary destinations and contextual paths

| Home | Secondary destinations | Contextual capabilities retained |
|---|---|---|
| Home | Collection dashboard | Valuation, cost/gain, movers, game/set/rarity breakdowns; empty-state capture/catalog |
| Collection | Cards/copies, Archived, Add cards, Want-list/cart | Quick capture, reviewed batch scanning, bulk entry, owners, locations, finishes/prints, reservations, restore and cart optimisation |
| Cards | Catalog, Leaders | Card detail, both faces, set filters, prints/prices/marketplace, owned lots, decks; SL set-review link |
| Decks | Existing discovery filters (all/built/virtual as provided), create | Leader-first/AI creation, builder, legality, allocation, built state, storage, analysis/swaps, shortfall shopping, offline readiness |
| Arena | Play, Games, Learn, On this device | Mode/deck readiness, continue, invitations/waiting, live board, completion/rematch, tutorial, local/offline preparation |
| Insights | Meta, News | Regional results, source decklists, card releases and set analysis (SL-only) |
| Account | Identity, Devices, Sign out for players | Login, join confirmation and legacy password entry are separate authentication flows |
| Settings | Appearance, AI & integrations, Data & sync, Storage locations, Users & access | Current settings sections remain on `/settings` unless an implementation deliberately introduces new routes |
| Admin | Rules workbench, Match review, Feedback, Testing & stats | Rule builder/review/reference, game debug, replay export and testing-run detail; development previews remain separate |

Settings side navigation must retain **Appearance** (current device theme and turn lighting), **AI & integrations** (provider selection/configuration/testing and current authorization), **Data & sync** (catalog, prices/FX, CardTrader, regional results, recent runs), **Storage locations**, and **Users & access**. Legacy logins remain nested under Users & access. Only the last two have separate existing page routes; other entries are proposed section navigation within `/settings`. Players currently cannot enter Settings: keep `/me` reachable and do not imply that new personal settings permissions have shipped.

Admin Rules secondary navigation: Queue, Guided review, Game rules, Keywords, Language. The builder is contextual to a rule record. Existing `/all` and `/patterns` paths redirect to queue state and should keep working, not acquire duplicate navigation entries. Match-review/debug/feedback routes retain private-state safeguards. A normal player reporting a bug from the board is different from opening the SL-only feedback-management list.

## Preservation rules and limits

- Both Masters and Fusion World remain available in catalogs, collection and decks. The current arena engine plays Masters (`dbs`) only; a Fusion World deck is not made playable by a new visual design.
- Readiness, deck legality, ownership, built/reserved state and offline eligibility remain separate facts. Preserve reasons for refusal and hidden selected-deck recovery.
- Dynamic detail routes inherit the primary navigation home but retain origin-aware back links. Cards reached from a deck still open the same card detail; no duplicated feature page is needed.
- APIs, auth redirects, cron mutations, public offline resources and the manifest are included for completeness but are not navigation tiles. `kind=action` marks a handler with a mutation/auth side effect (including mixed GET/POST handlers); `system` marks data/resource/redirect-only routes. A page containing form/server actions is still a page.
- Public offline entry intentionally differs from signed-in local play. Keep curated public pack resources separate from private own-deck pack endpoints.
- Access labels describe current code with authentication configured. In deliberately unconfigured local development the auth layer treats the viewer as an SL. Menu visibility never replaces server-side checks.
- This is static source review, not a runtime/security audit. The existing component audit is supporting architecture context. No production data, API actions, AI calls or mutations were run.
- Public static assets such as icons, the service worker and card art are not application routes and are outside the table. Their install/cache behavior must remain intact. Server actions are mapped as screen capabilities rather than treated as separately routable pages.
