A keyword is a word, not a paragraph

Every keyword on a Dragon Ball Super card means the same thing every time it is printed. The reader should show it as a badge, put the numbers that change into the badge, and keep text rows for the skills that are actually different on each card.

Built from the arena's own keyword list (src/lib/arena/glossary.ts, 39 keywords, 6 conditions, 9 skill types) and the full Masters catalog from deckplanet. Across the catalog, no fixed keyword prints its reminder in more than three wordings once numbers are set aside, so a written row adds nothing a player has not already read.

Rules for building it

Seven rules

  • One strip, then rowsKeywords (classes 1, 2 and 5) render as one wrapping strip at the top of the panel. Text rows follow, for skill types and class 3.
  • Count only real skillsThe header counts rows, not badges: "1 skill", not "3 skills", for BT3-051.
  • No raw markup{u}{u}{2} becomes two blue pips and a grey 2; <Grand Supreme Kai> becomes "on Grand Supreme Kai".
  • Same order everywhereBattle keywords first (Strike, Critical, Dual Attack, Blocker), then protection (Barrier, Deflect, Indestructible), then play keywords, deck rules last.
  • Tap explains, Full text provesA badge's tap shows the app's one-line meaning. Full text still shows the printed words, for the player who wants them.
  • Granted keywords look grantedA keyword another card gave this one gets a dashed outline and the source in its popover ("from Kibito Kai, this turn").
  • Live where the engine knowsBond, Sparking and Over Realm show met or not met from the engine's counts. Static text never claims a state the engine has not checked.

Building it

What changes in the app

Data already there. card.abilities marks keyword lines (category: "keyword") with their tags, and glossary.ts has each keyword's group and meaning. The class for each keyword is a new field on KeywordDoc, so a new keyword cannot ship without one (the typecheck already enforces an entry).

Reader. card-reader-model.ts splits readerAbilities into a strip (classes 1, 2, 5) and rows (skill types, class 3). A small parser reads a keyword line's values: cost tokens {r}{u}{g}{y}{b}{N} into pips, <Name> into a target, and the number after the keyword into its count. CardReader.tsx renders the strip above the rows.

Board. ArenaCard's keyword chips become the icon column; the icon set above is drawn on a 24-unit grid at 2.2 px stroke so it holds at 12 px.

Check. A verify script asserts every keyword in KEYWORDS has a class and that no class 1 keyword ever renders as a row.
