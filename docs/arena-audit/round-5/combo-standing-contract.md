## Stage 2a — standalone board adapter

The standalone observer now derives policy sources, physical holders/owners, source controllers and battle roles from actual ctx/game/state. The local typed state extension is still unimported by native writers. Explicit initialization is restricted to a fresh game and refuses existing legacy history; ordinary reads never initialize a missing affected history. Legacy-only contexts remain unchanged.

Synchronous transaction tokens bind the actual context, game and state object plus the original validated history. New area/holder/epoch facts require actual arrival witnesses. After a mutation, the adapter stages the mixed history and existing R475 grant-deletion receipts together, validates the resulting observation and grant invariant, then publishes only those ledgers. Original effect IDs and native queue/frame references are retained. Saved reloads receive a read seal only after the actual observer and grant receipts validate; stale zones/roles do not silently repair history.

The new staged-board suite uses full Goku, Prum, Pan, King Vegeta and Whis definitions. It proves threshold/role changes, owner versus physical holder, resolved keyword/copied-Auto deletion, non-resurrection and fresh re-grant, source whole/line negation, and same-epoch Battle-to-Combo mixed-policy transitions. Whis's ordinary Battle self-protection is inactive in Combo under RM9-1-3; it is not reused as all-area protection. Copied source/protection policies, standing grant regeneration, area-qualified/broad protection and timed protection remain explicit bounds. Missing receipt/capture/arrival history refuses before either ledger is published.

These are adapter tests on staged native state, not RULES.apply gameplay or admission. Actual movement/cleanup, pending-trigger dispatch, public state integration and privacy remain stage 2b work. In particular the suite's raw area transfers intentionally preserve epochs to test occurrence identity; they do not prove native cleanup semantics. The stage 2b batch/write plan is preserved in the shared review artifact `combo-standing/stage2b-writer-plan.md`.
