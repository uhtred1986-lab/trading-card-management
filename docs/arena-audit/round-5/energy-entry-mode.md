# R480: Energy mode before arrival observation

The script mover formerly placed the card, emitted its movement, then ran Energy-Exhaust's charge-limit hook. An explicit Active mode applied by the script afterward could override Exhaust. A conditional self negation could also count the arriving card in Energy, even though its condition was false immediately before entry.

The mover now reads effective keyword instances through `hookBodiesFor(..., "chargeLimit")` before placement and old-occurrence cleanup, and sets final mode in the placement operation. The bounded interpreter accepts only immediate self `modifyAttr` instructions setting Rest Mode. Empty hooks, other targets, Active modifiers and other effect shapes explicitly refuse before placement; no declared body is silently discarded. Missing hooks impose no mode, and another keyword declaring the supported Rest body works independently of its name. Exhaust makes the arrival Rest; explicit Rest remains Rest. Completed-movement receipts and arrival observers see that final mode. The captured observation survives cleanup of an old timed keyword negation. Native charge uses this script path.

The script forwards requested mode for every destination, and uses the returned actual area when deciding whether to apply its ordinary late non-Energy mode. Thus a Drop-directed move replaced with Energy still respects Exhaust and requested Rest, while an Energy-directed move replaced with Battle retains ordinary explicit-mode semantics. Other native movers remain outside this change.

Scanning every shipped `.rules` file finds exactly one chargeLimit hook, the DBS Energy-Exhaust hook; Fusion has none.
