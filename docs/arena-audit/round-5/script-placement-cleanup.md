# R488 shared script placement cleanup

2026-11-06. Preparatory refactor for exact Energy-entry projection; no new optional origin or card admission. RM 3-1-4 and its carryover exceptions distinguish new-area target cleanup from carried effects. Continuous effects last for their specified duration (1-7-2-2), so the existing mover ends effects with `until: whileSourceInPlay` when their source leaves Battle, including effects on other cards. This change shares that existing behavior instead of independently reproducing only target cleanup in the clone.

`script-placement-cleanup.ts` extracts the script mover's post-placement, pre-stamp non-trigger state work: clear the moved card's and released materials' public Auto reveal markers; remove target effects when the original carry/area decision requires it; end Battle-source-duration effects on departure; preserve the existing actual Battle arrival bookkeeping. The helper receives the original area and carry decision plus the actual native MoveRecord, including its final destination and released cards. Its only event output is the existing effect-ended logs through the caller's array. It emits no movement, pends no Auto, applies no replacement, and schedules no field cleanup. The live host continues to own the transaction, raw placement, new Energy stamp, standing settlement, result reporting, movement/trigger emission and field cleanup in their original order.

`projectEnergyEntryCleanup` in the Energy runtime clones once, captures a local standing transaction, performs the existing candidate-mode Energy placement, runs the shared cleanup with private logs and settles before returning the clone. The existing source/arrival protection comparison now uses this function. In particular, a Battle departure correctly removes source-duration effects on other cards before reading protection or standing generations. No function/token is persisted, and neither live state nor its events/pending queue is mutated. The projection is internal mechanism support, not a new origin admission API; preflight still refuses optional Battle entry.

The native proof compares the complete projected board with the actual host's settled board for plain owned Battle-to-Energy, both seats and Active/Rest candidate modes. It independently asserts removal of target effects and source-duration effects on another card, retention of unrelated game-duration and other-source effects, reveal cleanup, and unchanged input. A timed source negation on an all-other-Battle standing negator ends at departure and creates the expected new active generation identically in clone and actual movement. A separate protection effect on another card disappears in the projection. An arrival-Auto control demonstrates that only the actual host announces the pending Auto; the projection retains the original pending queue. Existing native Battle/Combo carry, same-area movement, placement bookkeeping and released stacked-material reveal cleanup are compatibility controls, not new optional-stack admission.

The old mover comment cited RM 5-5-4 for placedThisTurn bookkeeping, but the current manual's 5-5-4 describes failed-play disposal. The helper preserves the bookkeeping without repeating that inaccurate citation; no placement semantics changed. No flow/play/zone/trigger/state/program code was modified, including R454's separate movement-lifetime distinction.
