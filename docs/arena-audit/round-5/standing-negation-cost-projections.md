# R477 cost and projection prerequisite — WIP, no catalog admission

Source contract: `script.ts`'s `costReduction` execution creates one `group` for the resolved target set when uses are counted, including its specified-cost branch. `costs.ts:spendUses` decrements every selected coupon, then removes every sibling of a group whose selected member reached zero. Selection is captured before consumption. All such removals form one timing; iterating siblings to assign standing-source priority would be incorrect. Even a decrement with no expired effect changes the freshness witness and must finish settlement. The no-history path retains its existing removal/log order.

The source code currently creates groups only for cost modifiers, while the continuous-effect schema does not restrict group members to that kind. Synthetic cross-kind groups therefore require explicit boundary proof; they are not evidence that a printed card creates that combination. Activation timing after cost-driven changes remains under review in this WIP.
