# R477 native mutation adapter map — no gameplay admission

The synchronous prototype API is `captureStandingNegationMutation(ctx, state)`, followed by a native mutation on that same working state, followed by `settleStandingNegationMutation(ctx, state, token, { arrivals, enablingOrder })`. `assertStandingNegationSettled(ctx, state)` is read-only. Captures are opaque in-memory tokens bound to the exact context/state and prior history; they cannot survive serialization or a saved choice. Resume each choice with a new capture before its next synchronous slice.

`vm/index.ts:applyInner` already clones the previous state before running an action. Host closures and script frames retain references into that working state. The adapter therefore does not clone or replace the whole state, frames or queues: it validates next history and a cloned resolved-grant receipt array, then publishes only those two metadata fields. A failed settlement publishes neither field and propagates to existing action isolation. A token is consumed only after successful publication; a changed prior history invalidates an old capture, including one whose earlier settlement failed.

A grant resolving while a target remains suppressed must be captured by R475's normal writer and then marked deleted by settlement, even when the source/target graph is unchanged. Read assertion checks that invariant separately from the observation fingerprint. No fake timed negation effect or inferred legacy receipt is introduced. Copied negator/protector observation remains bounded, so this does not claim general copied standing-skill support.
