# Standing read lifetimes

Separate follow-up to R528 Stage B WIP, based on worker 9cb6e9ef. No card admission, saved schema, compiler or no-history optimization.

The full native run and profiling exposed repeated canonicalization of all definitions, programs and history from each attribute read. `readingBoard` already owns a synchronous immutable statics lifetime. The closed runtime wrapper now validates before entering that lifetime, allows v1/v2/v3 explicit and no-context readers to reuse those facts only for the exact context/state/actual game, and validates again before returning. Entry and exit compare complete immutable canonical dependency values, including the full state, all definitions/scripts, resolved token/copy definitions and actual/pinned game. Merely reissuing a seal on a changed-but-valid board cannot satisfy that comparison.

Different passed game objects use guarded forced-raw validation. No-history boards retain their existing validation path. Nested exact identities reuse the original lifetime; different identities get their own validation and restore their parent's scope. Exceptions retain their original identity. Thenables are rejected rather than extending scope asynchronously. No result, fingerprint or authority survives the callback.

All three family invalidators revoke every matching active lifetime. Writer guards refuse before mutations and poison that lifetime even if caught. Explicit guards cover family initialization/capture/require/settlement, physical movement, effect insertion/deletion/delays, payment/use consumption, activation execution, flow/run/draw/shuffle, and the host's scalar, face, token, event, queue and frame writers. Ordinary projection writers on distinct cloned states remain allowed. Direct arbitrary JavaScript assignments cannot all be intercepted; the successful-exit dependency comparison detects changes and prevents returning the cached result.

Read-call audit: legal actions, rejected actions, ability availability, board view, battle view, candidates, Combo eligibility, zero-power checkpoint snapshot and public snapshot wrapper. The zero-power callback writes only local candidate lists; publication follows its return. Choice previews resolve descriptions/selectors only. Attack and Blocker previews use the engine's private cloned apply boundary; attack reuse mutates that disposable result, never the original state. Snapshot concealment changes newly constructed projections.
