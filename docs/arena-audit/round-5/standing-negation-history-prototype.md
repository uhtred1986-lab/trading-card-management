# R477 standing whole-negation history prototype

This is a pure transition prototype for the DB1-066 / BT10-153 all-other-Battle policy. No card is admitted, no compiler behavior changes, and no gameplay caller writes or reads this history. TB1-048, BT20-086 and BT23-070 are outside this stage.

The King Vegeta / SS3 Gotenks official FAQs establish first-active precedence and the temporary-negation handoff: if A is negated, B takes over, and A does not reclaim the effect when its temporary negation expires. The prototype retains surviving active generation serials before admitting newly enabled occurrences. Identity includes card, card ID, epoch, hidden incarnation, side, master, skill index and exact compiled record identity. Enumeration sorting is used only for stale-observation detection. Multiple newly enabled sources require an explicit order supplied by the mutation owner; no player/card-array order is inferred. An asymmetric graph that would suppress a surviving active source refuses pending a reviewed protection transition.

Inputs explicitly supply externally enabled sources and protection-filtered target edges. Reads require matching settled history, never assign history, and fail closed for affected legacy boards. Missing history on an unaffected board is harmless. The optional state field is a storage shape only. A future native initializer must create empty history before the first affected transaction; it must not infer old activation order from a loaded board.

## Native seams still needed

- `host.moveTo`, token creation and the play-arrival transaction: settle after the complete landing, including pre-entry timed negation, but before arrival Autos and post-arrival Counter evaluation. Low-level `zones.moveCard` alone is too early and lacks source/protection context. Preserve R422 already-witnessed arrivals.
- `effects.addEffect` / `endEffects` and source-ending cleanup: settle actual validity changes and timer expiry before subsequent projections. Resolve mutation ordering explicitly; a batch's enumeration is not evidence of simultaneous-effect ordering.
- Control, face/hidden incarnation, under-pile and skill-copy changes: update occurrence identity at the actual transaction boundary; the initial policy covers Battle sources only.
- Protection observation: newly arriving Whis / protected Son Goku apply their own protection immediately, but pre-entry timed negation suppresses it. Do not blanket-ignore existing standing suppression when evaluating a previously suppressed target's protection at timer expiry. Candidate enablement and target protection may need separate observation passes.
- Barrier is irrelevant to these non-choosing edges. Deflect must still work before entry and be suppressed after landing. Already-resolved Over Realm delayed cleanup survives subsequent standing negation.
- R475 resolved keyword/copy deletion receipts must be updated by mutation settlement, not queries. Standing grant reactivation needs its own reviewed generation semantics; these active suppressor generations are not standing grant generations.

Verification: `npx tsx scripts/verify/standing-negation-history-5.ts` covers 32 grouped cases across both seats, including first-wins/handoff, generation identity, serialization, read purity, explicit simultaneous ordering, protection-edge input, and stale/malformed/legacy refusal. No full gate, database access, dependency installation or support-count change is part of this prototype.

## Native observation prototype (second stage, still no admission)

`standing-negation-observation.ts` reads native Battle occurrences and already-stored programs directly. It does not invoke the compiler, statics, attribute projections or keyword readers. `externallyNegatedSkill` isolates resolved whole/index/kind negation from the future standing history reader. Complete unconditional exact all-other-Battle records become candidates even when a previous standing generation suppresses them; source identity contains the complete current script.

An explicit transaction carries the validated pre-mutation observation/history and actual arriving occurrences. Unconditional self `beNegated` protection applies for fresh arrivals unless externally negated. A previously suppressed protector remains suppressed when its original suppressor is still externally enabled. When the original suppressor ends, this prototype refuses the protection-reactivation handoff rather than inventing an ordering. It also refuses external-area protection auras, timed protection, copied skills, incomplete Permanent records and conditional/non-exact policy shapes. Those are explicit observer bounds, not claims that such boards cannot be supported later.

The fixture contains cached stored records from `recovery/intent-catalog.json` for DB1-066, BT10-153, BT1-043 and TB1-097. Tests stage those operation records explicitly for observation; they do not change runtime support gates. The cached Whis record joins its Permanent and Auto without whitespace and is partially unread, so its prefix is deliberately rejected. TB1-097 supplies the complete protection case. Fixing Whis's text boundary and rebuilding its stored record is separate work.

### Minimal writer hook proposal

1. Initialize empty history only when creating a new match. A loaded affected board without history refuses before mutation. Capture/validate the current observation and its history before each relevant transaction; persist the settled candidate snapshot or decode the history's canonical observation, never reconstruct priority from the current card arrays.
2. The native transaction supplies actual arrival occurrences and, where proven, source-enable ordering. Finish placement, pre-entry negation and movement cleanup on a working state, then observe and settle exactly once before `moved`/`played` Auto observation or post-arrival Counter queries. Publish state/history together only after settlement succeeds. A refusal must not leave a half-mutated match.
3. Timed effect add/drop/expiry transactions use the same boundary, with no arrivals. A callback from `addEffect` alone is insufficient: it lacks context, can occur during a larger landing transaction, and could expose intermediate generations. A low-level `moveCard` hook is similarly insufficient. Host token creation needs its own complete landing boundary.
4. Reader integration then combines resolved negation with validated settled whole-negation history. Candidate observation continues using the external-only gate, avoiding self-suppression recursion. Normal projections may validate but never settle. Before admission, wire R475 grant deletion into settlement and review standing grant regeneration, all movement/control/hidden/face mutations, pre/post Deflect and R422 witnessed-arrival semantics.

The observer's focused suite adds 40 grouped cases across both seats; the 32 history cases remain applicable. These are executable native-state observations, not end-to-end card gameplay proofs.


The observation transaction now also requires a pre-mutation Battle occurrence snapshot, including protected cards absent from suppression edges. Every previous candidate and target must match that snapshot. Both occurrence lists require exact structural fields and unique physical card IDs; identical previous occurrences cannot be relabelled as fresh arrivals, while a new epoch of the same ID is distinct. Malformed serialized witnesses fail with R477 rather than incidental property-access errors. This field is provenance, not authorization from serialized contents: the future native writer must bind the capture to its original transaction and source/parent receipts before any arrival privilege is admitted. No saved transaction can acquire that authorization merely by presenting these fields.
