# R427 — Original movement results on the strict price host

RM 5-8-2-2 and 5-8-2-2-1 require completion of the instructed action and distinguish replacement of that action. RM 5-8-2-2-1-1 requires the specified new area; 5-8-4 retains performed payments but prevents activation when payment fails. RM 5-8-2-3 separately allows explicit replacement/modification of the cost instructions. This patch changes only the strict host's ordinary `move` wrapper: it captures the native original-movement result, forwards a caller's observer exactly once, and requires successful original completion in addition to the existing destination/bottom-position checks. An explicit alternative or modified price is already a set of instructions to perform; its ordinary successful movement remains paid.

The failing native `auto-costs-549` scenario offered an optional opponent-controlled replacement that also sends the Battle card to Drop after the orb had been paid. Before the correction, selecting the replacement incorrectly activated the Auto and drew one card. It now leaves the moved card in Drop and the earlier energy rested, cancels that unpaid activation, and draws nothing. Declining the replacement completes payment and activates once after JSON reload. Existing mandatory redirected, effect-only, and differently redirected price controls remain intact. The new eight-case `cost-movement-result-5` suite covers both seats, original/same-destination/different-destination movement, already-modified destination instructions, and exactly-once observer forwarding. These are typed protocol/native-mover controls, not a claim that a named printed card creates a replacement with that same destination.

Validation: full `auto-costs-549`, eight new controls, `counter-action-price-716` (including BT10-008's qualified alternative), `activate-battle-alt-742` (11 printed waiver records and runtime cases), and `activation-taxes-677` pass; TypeScript, changed-file lint and rulings (208, zero pending) pass. The compiler, text readers, schema and language fixtures are unchanged, so there is no new stored-record field delta. The broader runtime effect intentionally applies wherever the shared strict ordinary-move price host is used.
