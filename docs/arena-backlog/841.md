## Scope and acceptance
- [ ] Add a training session adapter and versioned synthetic card/deck fixture under proposed src/lib/arena/tutorial/. Follow contract.ts and local.ts; isolate tutorial code from production rules semantics. Expose the existing session capabilities honestly.
- [ ] Fixed opening and explicit three-life training setup. Store definitions and precompiled rule data with the fixture; never compile card prose in the browser or mutate arbitrary production saves. Include enough zero-cost +5000 combos to demonstrate 10000 attacker vs 10000 defender (tie loses for defender), then 15000 defense surviving.
- [ ] Opponent script selects only current legal actions; covers charge/play, one safe attack and pass/response choices. Match progresses after player deviations, skipped charge or spending a suggested combo early: use a bounded deterministic fallback, not a stuck expected-card ID. Never read hidden cards to write learner hints.
- [ ] All state transitions occur through the engine/session. Duplicate actions, stale snapshots, restart and opponent advance cannot duplicate payments or skip player response windows. No polling/sleep-based correctness.
- [ ] Assert reproducible snapshots and a complete win/loss path, defense/pass/combo paths, illegal-action rejection and alternate legal choices. Match remains finishable after tutorial guidance is off.
