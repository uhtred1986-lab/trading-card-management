## Build

Add a local worker/session implementation with start/read/apply/advance/cancel/dispose messages, request and session IDs, expected revisions and typed results. Keep full engine state in the worker and project only the human view. Advance the pure policy in bounded batches with cancellation and yields.

## Acceptance

- [ ] A real worker starts and advances a fixed match; stale revisions, duplicate requests, wrong session/actor IDs and out-of-order responses cannot apply extra moves.
- [ ] Cancellation/dispose prevents late results from mutating the active session; bounded batches keep the UI responsive and preserve exact replay/RNG progress.
- [ ] Unknown runtime/policy versions and unsupported mechanics fail explicitly without network/provider fallback or fake game outcomes.
- [ ] Run focused scenario checks plus `npm run typecheck`, `npm run lint`, `npm test` and `npm run build` before finalizing code. For documentation-only work, verify commands, links and claims against observed evidence. Engine/rules changes also require reviewed `npm run contract:emit` output and the repository's `npm run arena:fuzz -- 40` gate; database-backed fuzz/live-device/paid checks unavailable to an agent remain explicitly unverified, not silently skipped. Compiler changes require glossary and signed-off readings/gap diffs. Run no live database writer.
- [ ] Attach scenario-specific evidence and limitations per acceptance bullet; preserve online behavior and completed #547 replay work. If an existing correctness issue owns a blocker, link it and leave this issue's affected acceptance open.

## Out of scope

IndexedDB persistence, server persistence changes. No new dependency, production configuration change, live database write or paid-provider call is authorized by this ticket.

## Delivered

- `src/lib/arena/local/protocol.ts` — the typed, versioned messages (`dbs-arena-local-match` v1) and both ends' validators.
- `src/lib/arena/local/worker.ts` — the host: one match per worker, journal and receipts, online mutation semantics, the local policy in bounded cancellable batches, explicit refusals and interruptions; `worker-entry.ts` binds it to a module Web Worker.

- `snapshot.ts`, `types.ts` and `vm/index.ts` needed no change: the worker uses `browser.ts`'s `projectSnapshot` and the existing `Action`/`PlayerId` types.
