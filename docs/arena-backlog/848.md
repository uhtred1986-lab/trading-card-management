## Delivery and validation policy — owner update
This section supersedes earlier per-worker full-suite, one-merge-per-issue and model-default guidance for this milestone (owner instruction).

**Orchestration:** GPT-6.1 Sol at medium reasoning is the default Codex coordinator and reviewer. Use concise issue briefs, changed-file diffs and acceptance evidence instead of repeatedly loading whole histories. Escalate only a concrete unresolved architecture/semantics/security finding to GPT-6.1 Sol at high reasoning. GPT-6 Luna handles bounded asset, manifest, mapping and documentation work; GPT-6.1 Sol handles UI/runtime implementation. Keep at most three parallel workers with disjoint files and no nested delegation. Record retries/review effort; cheapest capable model, not repeated unsuccessful cheap attempts.

**Worker checks only:** inspect the diff and run the smallest check that proves the changed behavior. Asset/data workers: manifest validation, referenced files/mapping consistency and a visual contact-sheet inspection. UI workers: focused harness/smoke for the changed outcome, cleanup/fallback and relevant phone screenshot. Audio workers: focused playback/mute/cancellation smoke. Runtime workers: targeted assertions for event routing/deduplication/cancellation. Run typecheck/lint when TypeScript/shared imports require it, once per ready handoff, not per asset or tiny commit. Documentation-only changes need link/content checks. No worker full npm test/build, full deck playthrough, engine regression, fuzzing, database-backed tests or repeated all-device/all-skin matrix. Re-run only checks affected by a fix or new failure. Provide commands, result and limitations in the handoff. Do not add tests that merely mirror implementation.

**One feature PR:** #851, #853, #854, #855, #856, #849 and #857 contribute to one integration branch and one final PR for the basic audiovisual feature plus tranche 1. Keep isolated worker branches/worktrees; optional draft PRs are review/handoff artifacts targeting the integration branch, never independent merges to main. The coordinator reviews each contribution, integrates it, and runs only affected smoke checks between contributions. Dependencies are satisfied by reviewed integration into that branch; do not wait for each issue to merge to main. Keep implementation issues open until the final PR lands. Its body maps each closing issue to concrete acceptance evidence; use Refs for incomplete scope.

**Final gate once:** after all feature/tranche-1 contributions are integrated, run the repository's final typecheck, lint, npm test and production build once on the exact proposed combined head, plus a concise real-UI smoke for attack/hit/block/negate, neutral fallback, audio/mute and skip/reduced motion. This is the only full-suite gate for this feature PR. No extra full-deck/engine campaigns, fuzz runs or live DB checks. The standard npm test may include existing engine checks; do not add a second engine/deck campaign. Repeat only affected checks after ordinary fixes; repeat the full gate only if broad changes or unresolved failures justify it. Coordinator reviews and merges this one PR after success, then checks Vercel status.

**Tranche 2:** #852 inventory and #850 current-deck coverage are separate follow-on work and do not block the basic feature/tranche-1 PR. The shared bulk-import validator and targeted asset/mapping/render smoke are the normal gate for later data-only tranches; do not repeat the full engine/deck suite per tranche. Unknown deck classification still requires review; no writes to live decks.
