## Problem

A [Permanent] that changes a card's energy cost changes `costOf` (the total the game charges). Target filters still read the printed `energyCost`, so the two numbers disagree.

BT3-005 Determined Super Saiyan Son Goku, front 10: "[Permanent] When your life is at 4 or less, increase the energy cost of this card in your Battle Area" (+2). At life 3 or 4, `costOf` becomes 5. Engine proof (20 Oct 2026): a "cost 3 or less" KO still targets BT3-005 at life 4. The printed skill is meant to prevent exactly that.

Code paths:
- `src/lib/arena/vm/filters.ts`, around lines 117-118: `costMin` and `costMax` read `energyCost`; `specifiedCostMin` and `specifiedCostMax` (around 153-154) read `specifiedCost` and `energyCost`.
- `src/lib/arena/vm/cards.ts`, around line 159: `PRINTED_BASE` maps `costOf` back to `energyCost` for the base layer only.
- `src/lib/arena/vm/triggers.ts`, around line 388: one trigger predicate is given `energyCost: attrs.costOf`. So two readers already disagree about which number is "the cost".
- `src/lib/arena/vm/activate.ts`, around line 724, reads `costOf` when it charges a price.

Receipt: the batch-3 receipt, row BT3-005 front 10, marked "flagged; engine design (filters vs `costOf`)".

## Decision needed (owner)

Which energy cost does a cost filter ("cost 3 or less", "energy cost of 2 or more") read for a card in play?

- (a) The current total cost, `costOf`, including [Permanent] increases and reductions (20-21).
- (b) The printed cost only, so increases and reductions are ignored for targeting.
- (c) Decided per skill, by the skill's own wording.

Rule Manual 1-2-2 defines total cost as the numerical energy cost including the specified cost, and 1-2-2-2-2 says what X is after a card enters play. Neither section says whether a cost filter reads a [Permanent] change. The same question covers 20-21 reductions, which move the same number, so the answer is not a one-card change. Official FAQ for BT3-005: not checked in this issue.

Until the owner decides, no code changes. Once decided, file the ruling with `npm run arena:rule` (or the card's record) first, per `docs/arena-backlog.md` section 5 item 6.
