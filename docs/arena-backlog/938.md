Refs #907. BT31-139 Absorb and Power Up: draw; choose your white Cell Battle Card; optionally put an Android from Drop underneath that chosen Cell; only if you did, play up to one white Cell costing at most 4 from Drop on top of the **originally chosen** Cell in Active Mode (Manual 23-2 on-top stacks, 9-6 effect processing).

Bug: the optional Android choice overwrote the host reference, so the saved draft played the new Cell `onto c1` (the Android) and left the original Cell beside it.

Fix (generic, no card id): the compiler records which choice a skill put *under* which (`Ctx.underHost`); a play's `onto` ("on top of the chosen card / the originally chosen card / that card / it") resolves to the root of that pile, and "originally chosen" is the first choice that is not itself a passenger. Only the host of an on-top play is redirected, `lastTarget` is not reset, and a skill with no nested placement compiles exactly as before.

Proof: `scripts/verify/cell-binding-938-939.ts` (registered in `scripts/verify-arena.ts`) compiles the printed skill, writes it as stored rows, reads them back from JSON and plays it on the real VM on both seats: two candidates at every stage and either host, Android under the original Cell, new Cell on top in Active Mode carrying the pile, unrelated hosts and the opponent's board untouched, decline of the optional placement / no Android / decline of the replacement all play nothing, wrong-seat / wrong-colour / wrong-trait / over-cost / forged choices refused, JSON reload at the pending replacement choice. A negative control runs the old record (`onto c1`) and shows the original Cell left beside the new one.

Acceptance:
- [x] Original chosen Cell preserved across the nested choices through generic choice references; no card-id branch; `lastTarget` not blanket-reset.
- [x] Full printed skill through stored rows and the real VM (above).
- [x] Declining or having no Android plays nothing; the replacement can be declined; refusals covered; both seats; reload at a pending choice.
- [x] Glossary updated ("Tokens a play just made, and a host that stays the host").
- [ ] Full-catalog reading/gap deltas (`arena:diff`/`arena:reprobe` need the database; the owner or coordinator runs them).
- [ ] Live refresh of the saved BT31-139 draft: coordinator-owned, exact card/face/skill guarded, preserving non-compiler/confirmed/corrected ownership.

Caveat: the repository holds no printed text for BT31-139 (the catalog is in the database). The fixture uses the issue's own description in this app's usual spelling; every way of pointing back at the host (“the chosen card”, “the originally chosen card”, “that card”, “it”) is compiled and checked to land on the first choice, so a different but equivalent printing reads the same. The card's real text should be spot-checked in the workbench once the draft is refreshed.
