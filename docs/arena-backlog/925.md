Plain Union-Fusion in keywords.rules uses a generic choose(2, asPrinted), so two cards of the same character can be selected even though activation verified a complete pair. Potara chooses first from a broad printed filter and second after playing; neither uses exact namedSet. The asPrinted filter applies the whole combined material description, losing correspondence between each named character and its own color/type/cost/power restriction. namedCandidates uses printed characters/power only after resolving a shared filter.

Prove then repair: one distinct physical card per required character; no two Gokus, reuse or stale choice; each name's color/type/power/cost qualifiers belong to that material (BT22-136 yellow Goku 5000 + blue Vegeta 5000; BT23-084 green Vegeta Z-Battle + green Goku; BT7-121 blue Kale + yellow Caulifla cost≥4). Fusion equal power remains required; Potara has no universal equal-power requirement. Test hand-only plus all supported area extensions, serialized choices, forged selections and multi-character cards. Update glossary. Existing fixtures keywords.ts and union-areas-541.ts prove only narrower cases.

Acceptance: focused printed-text/runtime regression proof, glossary and corpus-delta review, typecheck/lint/full tests/build. No live database writes. Keep unrelated gaps open.
