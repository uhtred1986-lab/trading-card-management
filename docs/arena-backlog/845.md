## Outcome
After the first two player turns and a demonstrated attack/defense, the player chooses to continue the same match with or without guidance.

## Acceptance
- [x] Offer handoff at a stable decision boundary after required concepts were demonstrated or explicitly skipped, never during a pending player response, modal review or battle animation. Say what was skipped honestly; avoid claiming mastery from clicks.
- [x] Keep hints / Play without guidance / repeat explanation choices preserve exact engine state, hand, life, energy, turn, RNG and opponent continuation. Hints can be restored from the existing menu at any time.
- [x] Turning hints off mid-lesson works too. Win, loss, replay and exit use honest practice wording, without friend-invite labels or production rematch behavior.
- [x] Versioned local persistence keeps lesson preferences/progress and match state together using existing local-runtime conventions. Handle storage refusal/corruption/version mismatch visibly with restart; never silently combine a new fixture with old lesson progress. No server persistence or analytics service.
- [x] Verify reload during intro, action review, opponent turn and after handoff; no duplicated actions. Prove an unguided complete game and optional guidance restoration.

Keep shared ArenaStage changes minimal; coordinate with coach owner. Existing prototype’s post-battle handoff is only a starting reference.
