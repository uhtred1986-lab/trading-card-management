**Source:** #788 spec §10 and the TinyFish note "reads more like a management interface than a Dragon Ball battle" (https://github.com/uhtred1986-lab/trading-card-management/issues/788#issuecomment-6171895727) · prototype: `attackConfirm` → Attack, `target` → KO, ☰ → Motion · `shots/followup/fx-*`, `fx-reduced-*`. **Tracker:** #795. **After:** UX 6.

## Build (`stage/motion.ts`, `stage/BattleParts.tsx`, `stage/Takeover.tsx`, `src/app/globals.css`)
- **Card lands:** a ki ring.
- **Attack:** the attacker lunges along the arrow while the arrow fires solid. The defender gets a burst and a shake, or a blue flash when it holds.
- **KO:** a burst.
- **Life loss:** the life number pulses and "−1 LIFE" rises from it.
- **Phase change:** the new phase chip pops, plus the existing banner.
- Every effect lasts under 0.7 s, follows the board's pace setting, and never delays a decision.
- **Reduced motion** (the OS setting; reuse the board's existing handling): no movement. The defender gets a red outline (blue when it holds), a KO'd card dims with a dashed outline, and "−1 LIFE" stays put. Same information, no motion.
