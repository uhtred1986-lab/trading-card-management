Tracking: Arena F1. Depends on F1-02 (`fusion/words.rules`) and F1-05 (a Fusion World deck can reach a
board). Plan: `docs/arena-fusion-world-plan.md` §3. Priority P2, size M, Sonnet. Skill `screen-proof`
for the before/after shots.

## Why

The board reads its words from the loaded ruleset (`words.rules` → `board-words.ts`, #159/#782), but
the stage components still lay out every dbs area by name: `StageZones.tsx`, `ArenaStage.tsx`,
`BattleParts.tsx`, `PromptPanel.tsx`, `AdminDrawer.tsx` and `shared-display.tsx` all mention `zDeck`
or `unison`. A Fusion World game has neither, nor a Warp. The board must draw the areas the game
declares and nothing else, from one source: `game.zones` of the snapshot's ruleset, through
`board-words.ts`.

## Build

1. **`src/lib/arena/board-words.ts`**: `wordsFor(game)` returns the dbs or the fusion table
   (`fusion/board-words.ts`, generated by F1-01's emit change); the snapshot already carries the
   game id (`Snapshot.game` — check `src/lib/arena/snapshot-core.ts`; if it does not, add it and run
   `npm run contract:emit`, which is a contract change to call out in the PR).
2. **`StageZones.tsx` and `ArenaStage.tsx`**: an area is rendered only when the game's words table has
   a word for it. Z-Deck, Z-Energy, Unison and Warp slots collapse (no empty frame, no label) for a
   fusion game; the dbs layout is pixel-identical (prove it with `shots:compare`).
3. **`BattleParts.tsx`, `PromptPanel.tsx`, `AdminDrawer.tsx`, `shared-display.tsx`**: the same rule
   for any Z/Unison-specific control (the Z-Energy counter, the Unison marker badge, the admin
   drawer's Z-Deck list); the energy marker counter stays (both games have markers).
4. The Fusion World manual's words: "Active Mode"/"Rest Mode", "Drop", "Life", "Energy Area", "Combo
   Area", "Battle Area" (p. 5) — in `fusion/words.rules` (F1-02 wrote first drafts; finish them here).
5. Phone layout (`CLAUDE.md`: 2-column grids, `tap` targets, `BottomTabs`): the fusion board at 390 px
   has no empty columns where the Z areas were.

## Out of scope

Deck builder and collection screens (they already know `game`); the tutorial; immersion packs.

## Acceptance

- `npm run checks`, `npm test`, `npm run build`.
- `npm run shots:compare -- /arena/game/<a dbs game id>` at 1440 and 390: identical before and after.
- A fusion game's board at 1440 and 390 (`shots:compare` on a locally created hot-seat game between two
  starters; the F1-07 synthetic decks are enough): no Z/Unison/Warp frames, no empty columns, every
  remaining area labelled with the fusion words. Screenshots in the PR.
