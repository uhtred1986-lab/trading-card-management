## Build

Add a rules-only entry point that can create/apply/query/project a pinned match in a browser worker without importing the legacy registry or server code. Make engine selection injectable at the narrow replay/snapshot seam if needed. Add a transitive build/import check; preserve online callers and their engine behavior.

## Delivered

`src/lib/arena/browser.ts` is the browser-safe rules entry: `createPinnedMatch` (validates the
bundle's hashes and interpreter revision, builds the pinned context, deals the game),
`legalMoves`, `applyMove` (never mutates its input), `projectSnapshot` (one seat's masked
`Snapshot`, the same projection the server builds) and `replayWith(engine, …)`, the injectable
replay seam `offline-replay.ts` now calls with `engineFor(row.engine)`. Only the rules engine plays
there; asking for `legacy` throws `LegacyEngineUnavailable`.

To keep `./engine` out of that graph, the engine-neutral pieces moved beside the files that
re-export them unchanged: `view-core.ts` (`abilityViews`, `tappable`, `revealedTo`, `viewerOf`),
`beats-core.ts` (`SKILL_LABELS`, `revealedMove`, `relateBeats`, `appendBeats`, `maskBeats`,
`EMPTY_BEATS`, `BEAT_CAP`), `engine-ids.ts` (engine ids, info, default/fallback) and
`snapshot-core.ts` (all of the old `snapshot.ts`, with the engine taken as a resolver in
`buildSnapshotWith`/`rejectedForWith`). `snapshot.ts` binds that seam to `engineFor`, so every
online caller and contract fixture is unchanged (`npm run contract:emit`: no fixture diff).

#640's import walker moved to `scripts/lib/import-graph.ts` (with a `forbidFile` rule and
`legacyEngineRule`), and its page server to `scripts/lib/module-server.mts`.
`scripts/verify/arena-browser-boundary.mts` (in `npm test`) walks `browser.ts` and the cores with
the legacy rule, proves the rule on a virtual graph and on `browser.ts` with a legacy, switch,
`@/db`, `node:crypto` or `process.env` import added, runs the fixed-seed scenario
(`arena-browser-scenario.ts`, fixture in `arena-browser-fixture.ts`) twice and compares every
step's portable snapshot with the online `buildSnapshot`. `scripts/verify/arena-browser-engine-browser.mts`
(needs local Chrome/Chromium, not in `npm test`) runs the same scenario in a module Web Worker
served as native ES modules, offline after load, and requires byte-identical results to Node.

Unverified here: `npm run arena:fuzz -- 40` needs `DATABASE_URL` (owner's run). The rules graph
still reaches the card-text compiler modules (`compile.ts`, `compile/*`) through existing rules
imports; they are portable and pass the boundary, but are bundle weight a later issue may trim.
