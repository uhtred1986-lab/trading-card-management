Refs #907 #966.

#966 left multi-card send prices unread because catalog cards carry several of the named characters and a run of `choose` ops can pick one card for two slots.

Acceptance:
- [x] A generic exclusion: `Selector.notIn` (rules language `EXCEPT $c0 $c1`) drops cards earlier choices of the same program bound. Schema validation (a non-empty list of names an earlier `choose` binds; only a `choose`'s own selector may carry it), language round trip, `describeSelector` words; old programs stay valid.
- [x] Payability is a matching (`vm/disjoint.ts`, augmenting paths), checked in `canPayPriceProgram`; each slot offers only cards that leave later slots payable; a forged duplicate is refused.
- [x] Read generically (no card ids): "send N <desc>, N <desc>, and N <desc> from SRC to WARP" and "place … from SRC in DROP" (either order). Changed cards: BT10-025, BT10-026, BT12-138, BT12-139, BT18-041, BT19-004, EB1-38 (back), P-286, P-287, P-441, SD16-03.
- [x] Printed text -> compile -> stored-row JSON -> real VM, both seats (`scripts/verify/disjoint-send-costs.ts`); glossary updated; reading delta in the PR.

Left unread: "up to" slots, "this card" slots, dash qualifiers ("—all red—", "both from your Battle Area"), a qualifier stated only on the last slot (BT12-039 "with energy costs of 1"), optional ("you may") sends (BT27-007), prices with a dash aside the condition readers do not fold (BT22-033), [Auto]/[Counter]/keyword prices (own payment planners), and "at the bottom of your deck" destinations.

**Source:** Bandai card list (BT10-025/026, BT12-138/139, BT18-041, BT19-004, EB1-38, P-286/287, P-441, SD16-03, checked 17 Oct 2026), `docs/arena-backlog/966.md`.
