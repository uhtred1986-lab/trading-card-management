Refs #907, #942. BT31-141 Cell Jr. Summon (white Extra, cost 2): “[Activate: Main/Battle] Play 2 Cell Jr. Tokens and they gain [Blocker] for the turn. (Cell Jr. Tokens have 10000 power, 0 combo cost, and 5000 combo power.)” Only the two tokens this activation made gain Blocker (19-1; Blocker is a continuous skill for the turn).

What changed:
- The shared `token` op takes an optional `as`. The VM binds exactly the instances that invocation created; none created binds the empty result and replaces any earlier value of the name. Schema, language print/parse and validation read it; programs without `as` are unchanged and still valid. `contract:emit` fixtures regenerated.
- `Cell Jr. Tokens` keeps its full stop in the clause splitter (a capital “Tokens” after “Jr.” is not a new sentence).
- `compileToken` names the tokens only when the sentence goes on to say “they/it/those tokens”; the track step then makes that name `lastTarget`. The printed skill compiles to `token(n: 2, as: t0)` then `grant(target: $t0, Blocker, until: turn)`: no choice, no choose-all, no card id.

Proof: `scripts/verify/cell-binding-938-939.ts` (registered in `scripts/verify-arena.ts`): stored row → JSON → real VM on both seats. A token already in play (mine and the opponent's) gains nothing; the two new tokens have Blocker, 10000 power, 0 combo cost, 5000 combo power, owned by the activator; two activations stay distinct; Blocker is gone when the turn ends; reload keeps it; Main activation and a Battle activation (attacker and defender) both work; zero creations rebinds to the empty result and a stale token gains nothing. Negative control: the “select all your Cell Jr. Tokens after creating” approximation over-grants the pre-existing token.

Acceptance:
- [x] Optional creation-result binding on the token op, schema/language roundtrip, old programs valid, zero creations binds empty.
- [x] Abbreviation read; full skill compiled to create 2 → grant Blocker to that result for the turn.
- [x] Serialized record → VM: old-token negative, new-two positive, Main and Battle, two activations distinct, stats/owner, turn expiry, reload, overgrant negative control (never written to production).
- [ ] Cell Leader (BT31-116) nested invocation context: not touched; its independent mechanics are not claimed. No whole-deck readiness claim.
- [x] Replacement proposal for the protected override: `docs/arena-backlog/evidence/939/replacement-proposal.md`. No database write in this PR; applying it is #942.
- [ ] Corpus reading delta (needs the database; coordinator/owner runs `arena:diff`). Only token clauses followed by “they/it/those tokens” change; others compile identically.
