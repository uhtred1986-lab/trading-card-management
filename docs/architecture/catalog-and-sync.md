# Architecture: catalog, sync and prices

Read before touching the catalog import, errata, card images, TCGplayer or CardTrader pricing, or the cart optimiser. Moved unchanged from `CLAUDE.md` (issue #382); the text is verbatim, so a comment that says "see CLAUDE.md" means this file.

## Data sources (verified 2 Sep 2026)

| What | Source | Notes |
|---|---|---|
| Card catalog | `https://api.deckplanet.net/cardsearch/{dbs_masters_cards,fusion_world_cards}?limit=500&page=N` | Paged, `src/lib/catalog/deckplanet-fetch.ts` (the API caps `limit` at 500 since 13 Oct 2026; pages are 1-based, `&offset=` is ignored): page 1 carries `meta.page_count` and `meta.filter_count`, pages 2..N are fetched sequentially (3 attempts on network/5xx), concatenated and deduped by card id. It **throws before any database write** on an error object, an empty or short non-last page, or a distinct total that differs from `filter_count`. One logical fetch per game; the `dragogodev/cgs` repo the spec names is only a *pointer* to the first. 6.5k cards for the original game, ~2k for Fusion World. Alternate prints appear as top-level entries **and** in `variants[]`; `shapeCatalog` collapses them to one card per base number + a print list. The Fusion World payload differs in three ways, all handled in `deckplanet.ts`: bare rarity codes ("SR", normalised to "Super Rare[SR]" by `normaliseRarity`), no character/era lists, and a numeric energy cost. **Its skill text carries typos** — see `errata.ts` below. |
| Card images | `https://storage.googleapis.com/deckplanet_card_images/{number}.png` | Hot-linked via `next/image`; a few prints 404 and fall back to a placeholder. **Fusion World is not in this bucket at all** — its art comes from Bandai's own card list, `https://www.dbs-cardgame.com/fw/images/cards/card/en/{number}.webp` (leaders `_f`/`_b`, alternate prints `_p1`, `_p2`…; no User-Agent or Referer check). `src/lib/catalog/bandai.ts` crawls the card list's series pages for the exact image names at catalog sync and only assigns URLs that exist, since deckplanet lists ~700 more alternate prints than Bandai shows. Whatever is still null afterwards gets the matched TCGplayer product photo (`_200w.jpg` rewritten to `_in_1000x1000.jpg`) from `fillMissingImages` during the price sync. The catalog upserts therefore `coalesce` `image_url` instead of overwriting it. **Small renders (arena board cards, strips, ghosts, overlays) go through `cardImage(url, size)` in `src/lib/catalog/card-image.ts`**, which swaps the TCGplayer `_in_1000x1000` suffix for `_200w`/`_400w` at render time; deckplanet, Bandai and CardTrader have no smaller size (probed 1 Oct 2026), so their URLs pass through. Stored URLs are untouched; zoomed review stays full-size (#384). |
| Leader faces | deckplanet `{number}.png` / `{number}_b.png` (sets before BT19 only) → else Bandai's original-game card list, `https://www.dbs-cardgame.com/images/cardlist/cardimg/{number}.png` / `{number}_b.png` (every set, BT1 onward) → else the CardTrader blueprint image / `back_image`. All of it HEAD-verified at catalog sync **before** the import (`verifyFrontImages`, `verifyBackImages`, `applyOfficialLeaderImages`). Fusion World leaders use Bandai's `{number}_f.webp` / `_b.webp`, the back inferred from the `_f` front and HEAD-verified the same way | Stored in `cards.image_url` / `back_image_url`. The upsert lets a stored deckplanet URL yield to the fresh (possibly null) answer and otherwise `coalesce`s, so a CardTrader or price-sync backfill survives a re-sync until a catalog source has the face. **TCGplayer's photo of a leader ("Front // Back") is the awakened side** — never use it as a front. `CardFaces` shows front + awakened when present. |
| Prices | `https://tcgcsv.com/tcgplayer/{27,80}/...` | **Requires a browser-like User-Agent** (401 otherwise). Category 27 is the original game, 80 is Fusion World; 27 also carries a stray duplicate of Fusion World's FB01 group, which is skipped there. Products join to cards on the printed `Number`; SR+ cards only exist as a foil sub-type, so `priceForFinish` falls back foil↔normal — and the foil sub-type is called `Foil` in category 27 but `Holofoil` in 80 (`FOIL_SUB_TYPES`). |
| FX | `https://api.frankfurter.app/latest?from=USD&to=EUR` | Daily. |
| CardTrader | `https://api.cardtrader.com/api/v2` | **Read-only client**, and every live call is gated by `CARDTRADER_ENABLED=true` (the owner enabled it on 2 Sep 2026 after testing). Never add cart/purchase endpoints without being asked. Quirks the docs omit: `/games` returns `{"array": [...]}` (the client unwraps it); `/expansions` is a bare array; Dragon Ball Super is game id 9 and **includes Fusion World expansions** (`fb*`, `fs*`), which now cross-walk like any other set; `fixed_properties.collector_number` is `BT14-113` on newer sets but bare `049` on older ones (see `collectorNumbers`). Crosswalk covers ~98 % of cards, mostly via `tcg_player_id` = tcgcsv `productId`. Cardmarket also files Fusion World under its `DragonBallSuper` category, but **TCGplayer does not** — `externalLinks` picks the search slug per game. |
| Claude | `claude-opus-5`, adaptive thinking, Zod structured outputs via `messages.parse` | Every call is recorded in `ai_runs` with token usage. |

- **Catalog is immutable app data**: `card_sets` → `cards` → `card_prints`. Ownership
  (`owned_cards`) always references a *print* so foil/alt-art copies are distinct; deck slots
  (`deck_cards`) reference a *card*, because any print satisfies a deck slot.
- **The source's card-text typos are corrected on the way in** (`src/lib/catalog/errata.ts`) — the
  arena's compiler reads text literally, so one missing letter can cost a whole skill. **Never fix
  one with an UPDATE**: the catalog upsert sets `skill = excluded.skill`, so a hand-edited row is
  silently overwritten by the next `sync:catalog`. `syncCatalogFor` re-checks every entry against
  the fetched payload and warns if one stops matching. Only unambiguous errors are corrected, and a
  name correction is checked against Bandai's art first, never guessed. Bandai's official errata to
  what a card *is* go in the same file (errata-official-2): `FIELD_CORRECTIONS` (card name, back name,
  character names, applied by `shapeCatalog` before the search text is built and re-checked against
  the payload like skill text) and `SPECIFIED_COST_CORRECTIONS` (written into `specified_cost`, where
  it wins over a hand entry; `-` means no colour requirement, BT19-140).
- **No card-number prefix belongs to both games** — BT/EX/SD/TB/EB/DB/XD/P/TOKEN vs
  FB/FS/FP/SB/ST/E — so `gameOfSetCode` is a lookup, not a guess. Watch the `E`/`E01` pair in
  `sets.ts` and `normaliseNumber`'s `BARE_SET_CODES`.
- **Prices are daily snapshots** (`tcg_prices` keyed by product/sub-type/day) so movers can be
  computed; `pricesForPrints` reduces several TCGplayer products per print to one Normal + one Foil
  figure.
- **Catalog, price and meta reads are cached until the next sync** (`src/lib/cache/`, issue
  #383): `unstable_cache` tagged `catalog` / `prices` / `meta`, with a 24 h TTL as the backstop
  for the `sync:*` scripts, which run outside Next and cannot expire a tag. **A new writer of a
  cached table must expire its tag** (`expireTagsFromRoute` / `expireTagsFromAction`); the table
  in `reads.ts` lists every read, tag and writer, and `scripts/verify-cache.mts` checks the
  wiring. Never cache anything that reads ownership, decks, arena state or a login there.
- **Optimiser** (`src/lib/marketplace/optimizer.ts`) is deterministic: greedy + exhaustive 1/2/3-seller
  subsets + removal local search, shipping counted once per seller.

## Pokémon: live source (TCGdex)

Pokémon (`game = "pokemon"`, `GAME_INFO.pokemon.catalog = "live"`) has **no imported catalog**; the sync jobs run over `SYNCED_GAMES` only. Plan: `docs/pokemon/plan.md`. Code: `src/lib/pokemon/`.

- **Source:** TCGdex, `https://api.tcgdex.net/v2/{de|en}/...`, no key. `tcgdex.ts` holds pure mappers (`hitFromTcgdex`, `detailsFromTcgdex`, `variantsFromTcgdex`, `recordFromTcgdex`, `mergeSearchHits`, `parseSearchQuery`) and the reads (`searchPokemon`, `getPokemonCard`, `listPokemonSets`, `getPokemonSet`). Every read is a plain `fetch` with `next: { revalidate: 86400 }` (about a day; the nightly refresh passes `cache: "no-store"`), 8 s timeout, one retry on a 5xx or network error (TCGdex answers a 503 now and then). A failure throws `PokemonSourceError` (`kind`: `unavailable | timeout | not_found | bad_response`); the routes answer 503 "Die Kartensuche ist gerade nicht erreichbar" and collection and decks keep working.
- **Search** asks German and English and merges by TCGdex id, so "Glurak" and "Charizard" find the same card. A collector number ("6", "006", "6/165", "Glurak 6") filters by `localId` and the set's official size; the source matches "contains", so the mapper keeps only the exact number. The list endpoint returns only id, number, name and (sometimes) image: a search hit carries no price, no variants and no legality (`null` / empty), and its category and first type are known only when the search filtered on them. Set name and size come from the cached set list. `getPokemonCard` fills the rest.
- **Language split:** language-neutral rule fields (`stage`, `basicEnergy`, `onePerDeck`, `evolveFrom`, legality, variants, prices) come from the English record; `cards.name`, display strings, attacks and `cards.colors` prefer German. Prices are Cardmarket EUR trend/low in integer cents per variant (`variants_detailed`; the card-level block when the record has no per-variant prices: normal under `trend`, reverse under `trend-holo`); `thirdParty.cardtrader` is stored as `card_prints.ct_blueprint_id` (whether it is a usable CardTrader blueprint id is plan §3 step 1, not proven by this lane).
- **`ensurePokemonCard(db, tcgdexId)`** (`store.ts`) is the **only writer** of Pokémon rows in `card_sets` (`PKM-<setId>`, `line = "pokemon"`), `cards` (`PKM-<tcgdexId>`) and `card_prints` (`PKM-<id>` for the normal print, `PKM-<id>_<variant>` otherwise). It runs when a lot, a deck line or a wish refers to a card, in the same transaction (the network read happens before it: `loadPokemonCard`), and expires the `catalog` cache tag. Callers: `src/lib/pokemon/collection.ts` (behind the Server Functions in `src/app/pokemon/actions.ts`). Idempotent; `coalesce` keeps a stored picture, text, HP, CardTrader id, price or release date the source stopped sending.
- **The errata exception.** "Errata are fixed in `errata.ts`, never by UPDATE" and "keep `coalesce` in the catalog upsert" were written for a synced catalog. For Pokémon the source *is* the catalog: `ensurePokemonCard` and the refresh state what TCGdex says now, nothing is hand-edited, and `errata.ts` does not apply to these rows. A card nobody refers to any more stays as a row.
- **Nightly refresh.** `/api/sync/prices` calls `refreshPokemonCards(db, { budgetMs: 90_000 })` after the Dragon Ball price sync, caught on its own so it can never fail that sync. For every stored Pokémon card something refers to (a lot, a deck line or a wish), oldest-refreshed first, it re-reads the English record fresh and updates `details.legal`, `details.regulationMark` and the prints' `market_*` columns (a CardTrader id the source gained too). Single failures are counted, not thrown; a spent time budget leaves the rest for the next night. Its summary is in the cron's JSON (`pokemon`), not in `sync_runs`.
- **Image hosts** are listed twice by hand (`next.config.ts` `images.remotePatterns`, `public/sw.js` `ART_HOSTS`); `assets.tcgdex.net` is in both and `scripts/verify/image-hosts.ts` (in `npm test`) fails when the lists differ.
- **Proof:** `scripts/verify/pokemon-tcgdex.mts` runs on recorded responses (`scripts/verify/fixtures/pokemon/`) and PGlite, with `fetch` stubbed. Re-record a fixture by saving the live response of the same URL.

## Pokémon: CardTrader, prices and the cart (lane F)

Plan: `docs/pokemon/plan.md` §3 step 1 and §8. Code: `src/lib/marketplace/cardtrader-pokemon.ts`, `wishes.ts`, `cart.ts`.

- **Listings by blueprint id, not by sync.** Pokémon is a separate CardTrader game with far too many blueprints to sync into `ct_expansions` / `ct_blueprints`. `refreshListingsForCard(db, "PKM-…")` delegates to `refreshPokemonListings`, which reads `marketplace/products?blueprint_id=` for the `card_prints.ct_blueprint_id` of each variant and writes through the existing tables with **no schema change**: the `ct_blueprints` row is made on demand (`expansion_id` is nullable, so the direct path writes none), listings go to `ct_listings` with `card_id`, and `blueprintsFor` / the card page see them like any other card's. Read-only, gated by `CARDTRADER_ENABLED`, as before.
- **The id mapping is unproven.** TCGdex's `thirdParty.cardtrader` is *assumed* to be a CardTrader blueprint id; nobody has checked it (no token was available when this was built). So there are two paths. **Direct:** trusted only when the id returns products and a product name matches the card (and its collector number, where a product or a stored blueprint carries one). **Fallback**, when the direct id returns nothing or another card: `games` (the Pokémon game) -> `expansions` (matched to the set by name, else by code against the TCGdex set id) -> `blueprints/export?expansion_id=` (matched by collector number and name, as the Dragon Ball crosswalk does), then the corrected id is stored on the print and the listings come from it. A blueprint that fits neither shows no listings rather than another card's. The set-to-expansion matching by name is as unproven as the id. **To prove it:** `CARDTRADER_API_TOKEN=… CARDTRADER_ENABLED=true npx tsx scripts/pokemon-ct-check.mts PKM-sv03.5-006` (or a bare blueprint id with `--name` and `--number`); read-only, prints MATCH / MISMATCH for name and collector number per print.
- **Filters.** The cart takes `?lang=de|en` (default any) and `?cond=any` (default Near Mint) and applies them to **Pokémon listings only** (`applyListingFilter`, before `toListings`); a Dragon Ball listing is never filtered. A listing with no language or condition does not pass a filter that asks for one. Listings are EUR only and seller country / vacation rules are the existing ones. The optimiser is unchanged (`Listing` gained a display-only `language`).
- **Prices.** A Pokémon print has no TCGplayer product: `pricesForPrints` returns its `market_cents` (Cardmarket EUR, `market_currency = "EUR"`) as `PrintPrice.eurCents`, and `marketValueOf` uses it unconverted, where a Dragon Ball print keeps USD x the ECB rate. This feeds collection value, the dashboard totals (`summarise`), `/cards/[id]` and the `/cards` tile price. Movers (`basePricesAsOf`) stay TCGplayer-only: Pokémon keeps no price history. `externalLinks` takes the game: Cardmarket `/Pokemon/`, TCGplayer `pokemon`, and a CardTrader search by name and printed number (the internal `PKM-` id means nothing to a shop).
- **A player's wishes in `/cart`.** An SL sees "My list", one "Wishes of ‹name›" per player who has wishes (`wishSources`, `?for=<owner>`), and the deck source; a player sees only their own, and `wishesOf` returns nothing for another owner's name. The wishing player's owned / reserved counts are shown, not the SL's. This closes the gap for the Dragon Ball games too.
- **Mark as bought** (`markWishBought`, `markBoughtAction`, SL only): moves `quantity` copies of a wished card to lots stamped with the *wishing player's* owner name (`ownerFor`), price paid per copy in EUR, and reduces or removes the wish, in one transaction. For a Pokémon card the variant defaults to the cheapest listed variant that passes the filter and the language to the filter's (else the cheapest listing's, else EN); a Dragon Ball card takes its base print.
- **Proof:** `scripts/verify/pokemon-cart.mts` (PGlite, CardTrader stubbed from a synthetic fixture; not a recording).
